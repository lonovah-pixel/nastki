# STALKER Remote Admin — «Комендант» 2.0

Панель администрирования в стиле КПК для сборки STALKER RP. Полностью связана с ULX:
уровни доступа — это группы ULX, права — доступы `stalker_<право>` (раздаются в XGUI),
баны — общий список ULib. Без ULib панель работает на собственных таблицах, как раньше.
Оформление — общая тема сборки (`stalker_theme`), окно строится из `STALKER_STYLE`.

## Открытие

* `F7`, `!admin` в чате или `sta_menu` в консоли (клавиша меняется переменной `sta_key`).
* Отметьте цели слева, затем выберите раздел и команду. ПКМ по игроку — личное дело,
  «Отметить только его», копирование SteamID64, «Назначить уровень…».

## Первый владелец

Владелец назначается только из **серверной** консоли:

```text
sta_setrole 7656119XXXXXXXXXX owner
```

Либо пропишите SteamID64 в `lua/stalker_admin/sh_config.lua` → `Owners`. Владелец при входе
автоматически попадает в группу ULX `superadmin` (если его группа её не наследует).

## Уровни доступа = группы ULX

| Уровень | Группа ULX | Ранг | Права по умолчанию |
|---|---|---|---|
| Сталкер | `user` | 0 | нет |
| Наблюдатель | `operator` | 10 | view, observe, warn, teleport, logs |
| Модератор | `moderator` | 30 | + kick, ban (до 1 дня), mute, freeze, bans |
| Администратор | `admin` | 60 | + players, noclip, loadout, announce, zone, radiation, events, quests; бан до 7 дней |
| Комендант | `superadmin` | 90 | всё, включая бессрочный бан |
| Владелец | `superadmin` + Owners | 100 | всё, назначение любых уровней |

* Уровень игрока определяется по его группе ULX с учётом наследования: своя группа
  `headadmin`, наследующая `superadmin`, получит уровень «Комендант». Соответствие групп
  и уровней — `GroupRoles` в `sh_config.lua`.
* «Назначить уровень» в панели и `sta_setrole <SteamID64> <уровень>` в консоли меняют
  группу ULX (`ULib.ucl.addUser` по SteamID — работает и для офлайн-игроков; личные allow/deny
  игрока сохраняются). Недостающая группа (например, `moderator`) создаётся с наследованием
  `operator`.
* Нельзя действовать на цель с равным или более высоким уровнем и назначать уровень не ниже своего.
* Повторный бан заменяет прежний: бан, выданный более высоким уровнем, младший уровень не
  перезапишет (как и не снимет).
* При первом запуске с ULib уровни из старой таблицы `sta_roles` один раз переносятся в группы ULX
  (существующие записи ULX не перезаписываются).

## Права `stalker_*` в ULX/XGUI

Каждое право регистрируется как привилегия CAMI `stalker_<право>` (MinAccess `admin` или
`superadmin`) и как доступ ULib в категории **STALKER**. Операторам и модераторам доступы
выдаются напрямую, только нижней группе цепочки наследования. Дальше права настраиваются в
**XGUI → Groups**: «Комендант» спрашивает `ULib.ucl.query(игрок, "stalker_<право>")`, поэтому
изменения действуют сразу; рестарт сервера их не откатывает.

Права: view, observe, warn, kick, ban, mute, freeze, teleport, logs, bans, players, noclip, loadout,
announce, zone, economy, server, roles, settings, radiation, events, quests, craft, factions.

## Команды в меню ULX (категория STALKER)

| Команда | Действие | Право |
|---|---|---|
| `ulx stalkeritem <игроки> <предмет> [кол-во]` | выдать предмет STALKER | loadout |
| `ulx stalkerdose <игроки> <0–100>` | установить дозу радиации | zone |
| `ulx stalkerfaction <игроки> <группировка>` | назначить группировку | zone |
| `ulx emissionstart` / `ulx emissionstop` | запустить / остановить выброс | events |
| `ulx zonerebuild` | перестроить аномалии и артефакты | zone |
| `ulx stalkerrestock` | пополнить склады торговцев | zone |
| `ulx stalkerevent <id>` / `ulx stalkerstopevent <id>` | запустить / остановить событие | events |

Доступ к самой команде ULX по умолчанию — группа `admin`; дополнительно проверяется право
`stalker_*` и допуск к целям, всё пишется в журнал. Команды лежат в
`lua/ulx/modules/sh/stalker_admin.lua` — ULX загружает их сам.

## Баны и кик

* С ULib баны пишутся через `ULib.addBan` / снимаются `ULib.unban` и видны в XGUI → Bans;
  реестр в панели читает `ULib.bans`. Старые баны `sta_bans` один раз переносятся в ULib.
* Лимиты: модератор — 1 день, администратор — 7 дней, бессрочный — от «Коменданта» (настройки).
  Бан, выданный более высоким уровнем, нельзя снять более низким.
* Кик — через `ULib.kick` (без ULib — штатный `Kick`).
* Журнал действий хранится в `sta_audit` и дублируется в журнал ULX (`ulx.logString`).

## Разделы панели

* **Команды:** Дисциплина, Состояние, Перемещение, Снаряжение, Обстановка (группировка, доза,
  выброс, перестройка Зоны, склады, события), Сервер.
* **Реестры:** Реестр банов, Допуски (уровни и кнопка «Открыть XGUI»), Журнал.
* **Системы:**
  * **Настройки** — все параметры сборки из `STALKER_SETTINGS`: разделы по категориям, поиск,
    ползунок и поле для чисел, флажок, список вариантов, текстовое поле; «Сброс» к значению по
    умолчанию, изменённые подсвечены, фильтр «Только изменённые». Право `settings`.
  * **Радиация, Зона, События, Задания, Крафт, Группировки** — панели соответствующих аддонов
    (`BuildAdminPanel`). Если аддона нет — «Аддон не установлен». Права: radiation, zone, events,
    quests, craft, factions.

## Настройки (категория «Комендант»)

| ID | Что |
|---|---|
| `admin.ban_moderator` | лимит бана модератора, мин |
| `admin.ban_admin` | лимит бана администратора, мин |
| `admin.ban_max` | максимальный срок срочного бана |
| `admin.log_days` | срок хранения журнала, дней |
| `admin.self_god` | бессмертие для себя |
| `admin.max_targets` | целей в одной команде |
| `admin.page_rows` | строк на странице журнала |
| `admin.reason_bytes` | длина причины |

## Хранилище (SQLite)

`sta_seen`, `sta_roles` (без ULib — уровни; с ULib — только отметка владельца), `sta_bans` (без ULib),
`sta_banmeta` (ранг автора бана ULib), `sta_sanctions` (мут/гаг), `sta_audit` (журнал), `sta_meta`
(отметки одноразовых переносов). Это данные администрации — в полный вайп мира не входят.

Белый список оружия и список карт — в `lua/stalker_admin/sh_config.lua`.
