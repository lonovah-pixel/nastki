# STALKER NPC DIALOG AND TRADE — 1.0.0

Самостоятельный аддон NPC-диалогов и торговли для существующего **STALKER Inventory v1**, созданного в этой переписке. Уточнённый объём: стационарные NPC, дерево реплик, покупка/продажа/бартер; без квестов, фракций и репутации. Деньги DarkRP включены по умолчанию; тестовая экономика доступна только при явном выборе dummy.

Статус: реализация и автономные тесты готовы. В Garry’s Mod запуск не выполнен. Онлайн-генерация Figma заблокирована лимитом вызовов Starter-плана; новый макет в аккаунте не создан. В комплекте локальный генератор Figma и отдельно SVG-превью торгового экрана.

## 1. Краткое ТЗ

- Игрок нажимает E рядом с NPC; сервер проверяет расстояние, прямую видимость и существование зависимости.
- Персональная сессия содержит NPC, узел диалога, ревизию и срок действия.
- Дерево диалога задаётся конфигом. Ответы могут требовать наличие конкретного предмета. Доступность проверяется повторно на сервере. Последствия текущего объёма — переход к реплике, торговле или завершение разговора.
- Торговля работает с конечным общим складом профиля NPC. Копии одного профиля, например `sidor`, используют один склад.
- Корзина до 12 строк объединяет покупку и продажу. Разница оплачивается деньгами; при нулевой разнице это бартер.
- Сервер рассчитывает предложение, показывает итоговую сумму/вес и даёт 15 секунд на подтверждение. Подтверждение одноразовое. Изменение склада или рюкзака требует нового предложения.
- Цена учитывает состояние: `floor(base * (0.25 + 0.75 * durability / 100))`, минимум 1. Квестовых/фракционных модификаторов в этой версии нет.
- Продаются только предметы из рюкзака: экипировку сначала снимите в Inventory.
- Потребности, экипировка, предметы, вес, хотбар и сохранения игрока принадлежат Inventory; второго инвентаря игрока нет.

## 2. Дизайн и выбор UI

Выбран **Derma**: он работает с Lua-панелями существующего Inventory, позволяет переиспользовать рамки/шум/формат предметов, показывает модель NPC через DModelPanel и не требует браузерного JS-моста. DHTML, lua/html и сетевые JavaScript-команды не используются.

Окно 1120×700; масштаб `min(ScrW()/1180, ScrH()/740, 2)`. Верх: идентификация, баланс, 4 вкладки. Диалог: портрет NPC и ответы. Торговля: рюкзак игрока, склад NPC, корзина. Инвентарь: просмотр существующего рюкзака и переход к старому окну. Инфо: профиль и экономика. Звук и плавное появление используют встроенные ресурсы GMod. Иконки наследуются из реестра Inventory; если icon пуст, выводится `[ICON]`.

Локальный Figma-генератор рассчитан на три страницы:

1. **STNPC • 01 Foundations**: палитра, переменные, типографика, правила переноса.
2. **STNPC • 02 Components**: Button, Tab, NPCCard, DialogueRow, ItemSlot, Slider, Checkbox, Tooltip, Modal, Scrollbar. По 7 вариантов: Default, Hover, Active, Disabled, Selected, Danger, Success. Повторяемые элементы экранов — instances; контейнеры используют auto-layout.
3. **STNPC • 03 Screens**: диалог, торговля с двумя инвентарями, рюкзак игрока, склад NPC, подтверждение, уведомления.

Это статическая дизайн-система: Figma-прототип переходов не подключён. Интерактивность реализована в игре. Синтаксис генератора проверен Node.js, исполнение в реальной Figma пока не проверено из-за лимита.

### Создание макета локально

1. В Figma Desktop создайте **Development → New plugin**, выберите Figma Design и вариант без UI. Figma выдаст настоящий plugin ID.
2. Выполните `python3 figma/install.py /путь/к/созданному/manifest.json`. Скрипт сохранит выданный Figma ID и установит код генератора. Альтернатива: вручную скопируйте `code.js`, перенесите поля из `manifest.template.json`, сохранив ваш ID.
3. Откройте пустой Figma Design-файл и запустите плагин из Development. Нужны Oswald Regular, PT Sans Regular, Roboto Mono Regular.

Существующие страницы не удаляются. Повторный запуск останавливается, если уже есть страница STNPC Foundations. Если генерация прервалась, удалите только созданные этим плагином страницы/коллекцию и запустите снова. Превью `figma/trade-preview.svg` — отдельная иллюстрация компоновки, **не скриншот Figma/GMod**.

## 4. Сетевые сообщения

Все новые имена принадлежат **этому** аддону, префикс `stnpc.`. Старый протокол Inventory не переопределяется.

| Сообщение | Направление | Поля |
|---|---|---|
| state | S→C | JSON с длиной UInt16: сессия, профиль, узел, доступные ответы, ревизии, два снимка, баланс |
| choice | C→S | session UInt32, nodeRevision UInt32, choiceIndex UInt8 |
| quote | C→S | session UInt32, inventoryRevision UInt32, stockRevision UInt32, lineCount UInt8, строки |
| строка quote | C→S | buy Bool, index UInt6, count UInt10, UID String ≤96 |
| offer | S→C | JSON: ID предложения, итог, баланс после, вес, срок |
| confirm | C→S | session UInt32, offerID UInt32 |
| refresh | C→S | session UInt32 |
| close | оба | C→S session UInt32; S→C без payload |

Лимит входящего сообщения 16000 бит; 4 запроса/сек с запасом 8. Сервер ограничивает число строк, количество, адреса, проверяет UID, принадлежность, ревизии, цену, деньги, место, вес, срок, жизнь игрока, NPC и прямую видимость. Предложения не резервируют товары: конкурирующая покупка обновляет ревизию и инвалидирует старое подтверждение.

Клиент не отправляет цену, эффект, тип предмета, результат сделки или новый баланс. Удалённо выбрать произвольный NPC через net нельзя: сессия создаётся серверным `ENT:Use`.

## 5. Интеграция с Inventory и экономика

Используются реальные API исходника: `STALKER_INV.Items`, `Player:GetInventory()`, `EmptyInventory`, `NewItem`, `UID`, `Insert`, `FindUID`, `IsInt`, `Weight`, `ValidateSaved`, `CleanQuickbar`, `CaptureEquipment`, `SaveInventory`, `Sync`, `STALKER_INV_CanAction`, `STALKER_INV_GetBalance`.

`GiveItem` не используется для двух половин сделки: последовательные вызовы могли бы оставить частичный результат. Мост готовит копии, сохраняет их общей транзакцией и лишь затем публикует новое состояние. Он привязан к проверенной схеме **Inventory v1**: таблица `stalker_inventory(steamid,payload)`, формат version=1. Нужен `stalker_inv_storage sqlite`; в JSON-режиме торговля блокируется. Обычное управление Inventory остаётся доступным.

При dummy-экономике в одной SQLite-транзакции меняются существующая строка Inventory, строка склада и тестовый баланс. JSON-копия Inventory создаётся после COMMIT через штатный `SaveInventory`; rollback не оставляет новую JSON-копию. Продажи экипировки исключены, поэтому механика выдачи SWEP не дублируется. Метаданные экземпляра (durability, clip1, clip2, armor) сохраняются при покупке/продаже.

**DarkRP включается одной строкой в sh_config.lua:**

```lua
Economy="darkrp",
```

Адаптер использует `ply:getDarkRPVar("money")` и `ply:addMoney(delta)`. Он проверяет фактический результат: сторонний хук, изменивший сумму, приводит к отказу. DarkRP должен быть установлен и загружен; fallback на бесплатные покупки отсутствует.

DarkRP может сохранять деньги в другом backend/асинхронно, поэтому общей ACID-транзакции с его кошельком нет. До изменения денег создаётся журнал `pending`; после успеха — `committed`. При отказе выполняется компенсация и проверка баланса; при неопределённости игрок блокируется. После аварии запись pending не обрабатывается повторной автоматической выдачей.

Администратор сверяет фактические деньги и запись в `stnpc_journal`, при необходимости корректирует баланс штатными средствами DarkRP, затем выполняет:

```text
stnpc_resolve <transaction_id> verified
```

Команда только снимает блок после ручной проверки, не начисляет деньги и не выдаёт предметы. Не запускайте её вслепую. Удаление таблицы кошельков/склада сбросит их, поэтому перед изменениями делайте копию sv.db.

Склад NPC конечный, автоматически не пополняется. Начальный склад создаётся один раз; изменение `stock` в конфиге не сбрасывает уже сохранённые товары. Профиль не имеет отдельного ограниченного кошелька: выплаты продавцу разрешены в пределах MaxBalance тестового игрока. Торговые наценки, классы предметов и условия меняются в конфиге на сервере и клиенте одинаково.

## 6. Установка и использование

1. Установите предыдущий `stalker_inventory`. Этот архив не заменяет его файлы.
2. Скопируйте только **addons/stalker_npc_dialog_trade** в `garrysmod/addons/`.
3. Убедитесь, что сервер использует `stalker_inv_storage sqlite`. В DarkRP оставьте `Economy="darkrp"`. Только для отдельного теста в Sandbox выберите `Economy="dummy"`: стартовый тестовый баланс 5000.
4. Перезапустите сервер/карту, переподключитесь.
5. Superadmin: наведитесь на близкую точку пола и выполните `stnpc_spawn sidor`. Можно также создать STALKER Trader через spawnmenu.
6. Нажмите E рядом с NPC. Соберите корзину, нажмите «Проверить сделку», затем «Подтвердить».
7. Для постоянных позиций всех торговцев на карте выполните `stnpc_save`. После удаления/перемещения NPC сохраните снова.
8. Для EN: `stnpc_language en`, затем переоткройте диалог. Интерфейс и реплики переведены; названия/описания предметов наследуются из Inventory и остаются в языке его реестра.

Файлы `test_dependency/` — неизменённые три shared-файла старого Inventory для автономных тестов. Их **не нужно устанавливать в addons**. Они не запускают второй инвентарь.

## 7. Настройка диалогов и торговцев

В `N.Config.Traders` добавьте новый профиль с уникальным ID, `name`, `role`, `model`, `root`, `nodes`, `prices`, `stock`. `prices[id].buy` — цена продажи NPC игроку; `sell` — цена покупки NPC у игрока. Если направления нет, соответствующая операция запрещена.

Пример узла в существующем профиле:

```lua
news = {
    text = {ru="Что принёс?", en="What did you bring?"},
    choices = {
        {id="parts", text={ru="Детали.", en="Scrap."},
         requires={item="scrap",count=3}, action="trade"},
        {id="back", text={ru="Назад.", en="Back."}, next="greeting"}
    }
}
```

Требование проверяет количество в рюкзаке, ничего не расходует. Произвольный Lua из клиента не исполняется. Для серверных бизнес-ограничений доступен новый хук `STNPC_CanTrade(ply, traderEntity, lines, total)`: вернуть false для отказа. Это новый API данного аддона, не выдуманный API старого Inventory.

Отладка: `Debug=true` в sh_config.lua. Успешные сделки, SQL-ошибки и ручное восстановление всегда идут через ServerLog с transaction ID; Debug дополнительно печатает их в консоль. Чат-хуки PlayerSay не используются: разговор начинается по E.

## 8. Проверки

Автономный стенд: Python 3 + системная liblua5.4, Linux; запускайте из корня архива:

```sh
python3 tests/run_lua.py tests/inventory_core_spec.lua tests/trade_spec.lua tests/transaction_spec.lua tests/session_spec.lua
node --check figma/code.js
```

Пройдено: синтаксис 12 новых Lua-файлов; 83 assertions (30 прежнее ядро, 22 торговля, 19 транзакции, 12 сессии); 500 перестановок и 100 циклов покупки/продажи. Проверки SQL, net и DarkRP используют имитацию границ движка; они не подтверждают визуальное поведение Derma или реальную работу сторонних money-hooks.
