> **Сборка STALKER RP:** установка, настройка DarkRP и первый запуск сервера описаны в README.md в корне репозитория. Деньги DarkRP включены по умолчанию; членство — через вербовщика; меню лидера и суперадмина разделены. Ниже сохранена документация базовой версии аддона.

# STALKER Inventory — Garry’s Mod

Версия 1.0.0, кандидат для игрового тестирования. GLua / Derma, серверный инвентарь, SQLite + резервный JSON.

Макет: https://www.figma.com/design/b1L8C16BHkg59W15Fy9pkW?node-id=1-15

## Что сделано

- Окно 960×600 в стиле PDA: бронзовые рамки, тёмно-коричневые панели, процедурный шум с alpha 13/255, виньетка, царапины, плавное появление.
- 40 ячеек 64×64 (8×5), 9 ячеек экипировки (3×3), 9 быстрых ячеек 48×48.
- Уникальные UID предметов, стаки, состояние, масса; хотбар хранит ссылки на предметы и не увеличивает их число/вес.
- Перетаскивание с ghost-иконкой, hover, отдельный tooltip, двойной клик, контекстное меню, подтверждение разбора.
- Серверные проверки ячеек, UID, ревизии, состояния игрока, категории экипировки, лимита сообщений и частоты запросов.
- Использование медицины, еды, воды, боеприпасов; экипировка оружия и куртки; разбор в детали.
- Выброс всего стака в физический предмет и подбор по E с проверкой дистанции. Для подбора нужна свободная ячейка.
- Автоматическая масса, красный индикатор и коэффициент скорости 0.55 при массе >50 кг.
- Сохранение по SteamID64, загрузка при входе, экипировка при появлении, сохранение после действий, каждые 30 секунд, при выходе и остановке сервера.
- Вкладка артефактов фильтрует отображение, сохраняя реальные индексы ячеек. PDA показывает игрока и сектор. Вкладка карты поддерживает установленный материал карты.

Это самостоятельный инвентарь, а не автоматический импорт всех предметов/оружия игрового режима. Игровые ассеты S.T.A.L.K.E.R. в архив не включены. Иконки — разрешённые заданием `[ICON]`; модели предметов для выброса используют базовый контент Garry’s Mod / HL2. Шум создан процедурно.

## Установка

1. Из ZIP скопируйте папку `addons/stalker_inventory` в `garrysmod/addons/` на сервере. Итог: `garrysmod/addons/stalker_inventory/lua/autorun/stalker_inv_init.lua`.
2. Перезапустите сервер/карту и переподключитесь. Lua-файлы отправляются через AddCSLuaFile, noise.png — через resource.AddFile. Если сервер запрещает загрузку ресурсов, настройте FastDL/Workshop для материалов.
3. Откройте консоль клиента и выполните `stalker_inv`, либо нажмите TAB.
4. Новым игрокам по умолчанию выдаётся небольшой стартовый набор. Существующее пустое сохранение не считается новым игроком.
5. Для тестового сервера superadmin может выполнить `stalker_inv_give rifle 1`. Серверная консоль: `stalker_inv_give rifle 1 7656119XXXXXXXXXX`.

Для точного совпадения шрифтов с Figma установите на клиентском компьютере Roboto Mono, PT Sans и Oswald. Бинарные файлы шрифтов не включены. Если шрифт недоступен, движок использует замену; можно выбрать системные варианты:

```text
stalker_inv_font "Courier New"
stalker_inv_heading "Trebuchet MS"
```

Закройте и снова откройте окно после смены шрифта/масштаба.

## Управление

| Действие | Управление |
|---|---|
| Открыть/закрыть | TAB или `stalker_inv` |
| Открыть на удержание | `bind i +stalker_inv` |
| Своя клавиша через консоль | `bind i stalker_inv` |
| Выбор предмета | ЛКМ |
| Использовать / экипировать | Двойной клик или кнопка справа |
| Контекстное меню | ПКМ по предмету |
| Перемещение | Перетащить ЛКМ |
| Назначить хотбар | Перетащить из рюкзака/экипировки в быстрый слот |
| Использовать хотбар | Левый ALT + 1–9 |
| Очистить хотбар | ПКМ по быстрому слоту → убрать |
| Подобрать выброшенный предмет | E рядом с предметом |
| Обзор мышью при открытом UI | Удерживать ПКМ по фону окна |

`stalker_inv_key` принимает числовой код KEY_* (по умолчанию KEY_TAB). При своём биндинге на другую клавишу можно поставить `stalker_inv_key 0`, чтобы отключить встроенный опрос TAB и вернуть scoreboard. Не назначайте одну и ту же клавишу одновременно через встроенный опрос и через bind.

При открытии вызывается MakePopup и затем SetKeyboardInputEnabled(false), поэтому WASD остаётся доступным. Обычный поворот камеры и указатель меню разделены режимом удержания ПКМ. Активные поля ввода/чат не запускают горячие клавиши. ALT необходим, чтобы не заменять обычные слоты оружия 1–9.

## Настройки

| Переменная | Где | По умолчанию |
|---|---|---|
| `stalker_inv_storage` | сервер | `sqlite` (альтернатива `json`) |
| `stalker_inv_starter` | сервер | `1` |
| `stalker_inv_key` | клиент | код KEY_TAB |
| `stalker_inv_scale` | клиент | `1`, диапазон 0.65–2 |
| `stalker_inv_font` | клиент | `Roboto Mono` |
| `stalker_inv_heading` | клиент | `Oswald` |

Масса, палитра, начальный набор, список экипировки и размеры находятся в `lua/stalker_inv/sh_config.lua`. Сетка/размер протокола рассчитаны на 40+9+9 ячеек; изменение количества требует согласованного изменения core/net/UI.

Масштаб учитывает ScrW/ScrH и ограничивает размер окном экрана. Макет спроектирован для 1280×720 — 3840×2160, но визуальный тест внутри GMod ещё нужен на этих разрешениях.

## Свои предметы

Добавьте файл `lua/autorun/zz_stalker_inv_custom.lua`. Реестр должен совпадать на клиенте и сервере. Обработчик эффекта задавайте только на сервере.

```lua
if SERVER then AddCSLuaFile() end

local function RegisterCustomItems(S)
    S.RegisterItem("field_medkit", {
        name = "Полевая аптечка",
        description = "Восстанавливает 50 здоровья.",
        model = "models/items/healthkit.mdl",
        icon = "", -- Например: stalker_inv/items/field_medkit.png
        weight = 0.45,
        stackable = true,
        max_stack = 5,
        category = "medicine",
        stats = { health = 50 },
        durability = 100
    })

    if SERVER then
        S.Items.field_medkit.OnUse = function(ply, item, inv, def)
            if ply:Health() >= ply:GetMaxHealth() then
                return false, "Здоровье уже полное"
            end
            ply:SetHealth(math.min(ply:GetMaxHealth(), ply:Health() + def.stats.health))
            return true -- Ядро само расходует ОДНУ единицу.
        end
    end
end

hook.Add("STALKER_INV_Ready", "MyServer.Items", RegisterCustomItems)
if STALKER_INV and STALKER_INV.RegisterItem then
    RegisterCustomItems(STALKER_INV)
end
```

Выдача из серверного кода:

```lua
local ok, reason = STALKER_INV.GiveItem(ply, "field_medkit", 3)
if not ok then ply:ChatPrint(reason) end
```

`GiveItem` добавляет всё указанное количество либо ничего. `Player:GetInventory()` возвращает серверное состояние, на клиенте доступна только копия собственного инвентаря. Внешний код не должен напрямую изменять эту таблицу без синхронизации.

Для собственного SWEP добавьте `weapon = "weapon_my_rifle"`, `category = "primary"`, `clip1 = 30`, `stackable = false`. SWEP должен быть установлен на сервере и клиентах. Стандартные оружейные категории: `primary`, `secondary`, `pistol`, `throwable`; остальные: `helmet`, `armor`, `artifact`, `boots`. Для экипировки требуется count=1. Для брони задайте `stats = {armor=50}`. Для разбора: `salvage = {scrap=4}`. Запас магазина и остаток брони сохраняются при перемещении.

`OnUse` возвращает `true` только при успешном эффекте; `false, "причина"` не расходует предмет. Обработчик должен быть синхронным и не изменять инвентарь через GiveItem/Commit рекурсивно. Исключение перехватывается, но побочные эффекты стороннего кода автоматически не откатываются.

Износ — целое число 0–100, сохраняется и показывается. Автоматическая симуляция износа от выстрелов/повреждений не включена; её можно добавить серверной интеграцией. Характеристики произвольных предметов не меняют автоматически параметры SWEP. Шлем/ботинки предоставляют слот и данные для интеграции; базовая механика брони применяется только к куртке.

Иконку поместите в `materials/stalker_inv/items/...png`, укажите путь без `materials/` и добавьте `resource.AddFile("materials/stalker_inv/items/...png")` на сервере. Прозрачный фон PNG поддерживается. При пустом/ошибочном материале остаётся `[ICON]`.

## Интеграция

Хуки:

- `STALKER_INV_Ready(S)` — реестр готов.
- `STALKER_INV_CanAction(ply, action, item, zone, index, to, targetIndex)` — вернуть false для запрета серверного действия.
- `STALKER_INV_CanPickup(ply, entity, item)` — вернуть false для запрета подбора.
- `STALKER_INV_EquipmentChanged(ply, equipment)` — уведомление об экипировке.
- `STALKER_INV_GetBalance(ply)` — клиентский адаптер отображения денег.
- `STALKER_INV_Updated(inv)` — клиент получил snapshot.
- `STALKER_INV_DrawPDA(panel, width, height)` — дополнить PDA отрисовкой.

DarkRP: баланс читается через getDarkRPVar("money"), деньги не создаются и не тратятся. В Sandbox без адаптера денег отображается «— ₽». Потребности являются отдельной лёгкой моделью этого аддона; интеграции с DarkRP hungermod нет. Нативный резерв патронов SWEP не сохраняется этим аддоном.

Существующее оружие того же класса, выданное игровым режимом, не забирается и не дублируется. В Sandbox для тестирования пистолета отключите выдачу такого же оружия при появлении либо используйте другой SWEP. Сторонние оружейные базы с собственным инвентарём, броня другого аддона, смена DarkRP job и аддоны, уже определяющие Player:GetInventory(), требуют проверки совместимости. Для ограничений профессий используйте CanAction и соответствующие серверные hooks вашего режима.

Карта: добавьте материал и запись `STALKER_INV.Config.MapMaterials["gm_construct"] = "stalker_inv/maps/gm_construct.png"`. Без материала вкладка честно сообщает об отсутствии картографических данных; навигация/позиция игрока по карте не реализованы. PDA — локальная информационная вкладка, без заданий и мессенджера.

## Сеть и сохранение

Сообщения: `stalker_inv.sync`, `.request`, `.move`, `.use`, `.drop`, `.disassemble`, `.unbind`. Клиент посылает только действие, адрес ячейки, ожидаемый UID и ревизию. Количество, вес, деньги, item ID и эффект не принимаются от клиента.

SQLite: таблица `stalker_inventory` в стандартном `sv.db`. JSON: `data/stalker_inv/<SteamID64>.json`. По умолчанию SQLite приоритетен, но более свежая JSON-копия используется после сбоя записи БД. JSON backend доступен явно. Неизвестная версия/предмет/повреждённые обе копии блокируют загрузку без уничтожения исходных данных. Для восстановления верните удалённые определения предметов либо исправьте сохранение при остановленном сервере и переподключите игрока.

Изменения инвентаря сохраняются сразу. Переименование временного JSON имеет проверяемый fallback на запись файла. Аварийная остановка ОС, недоступный диск и сторонние эффекты не образуют общей распределённой транзакции: абсолютная защита от потери/дублирования при любом падении не заявляется. Если оба backend недоступны, игрок получает сообщение, ошибка записывается в серверную консоль.

Инвентарь сохраняется после смерти. Выброшенные предметы существуют до подбора, очистки карты, рестарта либо 15 минут; сохранения мирового лута нет. Боты хранят инвентарь только в памяти.

## Проверки и границы

Проверено 19 Lua-файлов парсером Lua 5.4; код избегает специфичных для 5.4 конструкций. Выполнены 60 assertions с подменой границ движка и 500 случайных перемещений. Это не исполнение GLua/Derma в Garry’s Mod.

Команда из корня распакованного ZIP, Linux + Python 3 + liblua5.4:

```sh
python3 tests/run_lua.py tests/core_spec.lua tests/server_spec.lua tests/persistence_spec.lua
```

Перед запуском на рабочем сервере выполните игровые проверки:

1. Открытие/закрытие TAB и командой, чат, WASD, ПКМ-обзор, 720p/1080p/4K.
2. Drag & drop на пустую/занятую ячейку; допустимая/недопустимая экипировка; слияние/полный стак.
3. Хотбар после перемещения, слияния, использования последнего предмета и переподключения.
4. Два клиента одновременно подбирают один предмет; успешен только один.
5. Выстрелить, снять/надеть оружие, проверить магазин; повредить броню, снять/надеть, проверить остаток.
6. Выбросить/подобрать оружие и броню, умереть/возродиться, проверить отсутствие копий.
7. Заполнить рюкзак и выполнить разбор, для которого не хватает места: исходный предмет должен остаться.
8. Выдать `stalker_inv_give scrap 400`, проверить >50 кг, индикатор и скорость, затем убрать лишний вес.
9. Переподключение/перезапуск с SQLite и JSON; ошибочное сохранение должно блокировать загрузку без стартового набора.
10. Повторить основные сценарии с конкретным набором DarkRP/SWEP/броневых аддонов.

## Личные тайники (обновление)

- Тайник — сущность `stalker_stash` в мире (ящик). Видна и доступна только владельцу, не имеет коллизии.
- Создание: кнопка «Тайники» в КПК (или `!stash`, `stalker_stash`) → «Создать тайник под прицелом». До 3 тайников, 20 ячеек.
- Открытие: подойти к своему тайнику и нажать **E**. Рядом с рюкзаком открывается отдельное окно тайника.
- Перенос предметов перетаскиванием: рюкзак ↔ тайник (на ячейку — точное место/обмен/слияние стаков, на фон окна — в первую свободную ячейку).
  2× ЛКМ или ПКМ по предмету в тайнике — забрать в рюкзак; ПКМ по предмету рюкзака — «Положить в тайник»; кнопка «Забрать всё».
- Настройки — `S.Config` (`MaxStashes`, `StashSlots`, `StashRange`, `StashUseRange`, `StashModel`).

Сценарии проверки: создать тайник, отойти дальше 150 units (окно закрывается), перенести стак на занятую/такую же ячейку, «Забрать всё» при полном рюкзаке, переподключение (тайник появляется снова), второй игрок не видит чужой тайник.
